# Cocoon — judge testing

Public link: https://coco-safe-routes.lovable.app

The public link shows the last published version; audit fixes await review and republishing.

1. Start with **Skip this and explore**, or **Let the light in → Enter Cocoon**. No account is required to explore.
2. Open **AI companion**. The no-account call requests real AI voice, capped at **2 minutes**, **2 starts/hour and 4/day per network/IP** (shared networks may share limits; global caps also apply). Review all three consents, then explicitly start and grant microphone permission. It uses the app’s Lovable AI credits. Cocoon does not save audio/transcripts; service/provider policies apply. The voice cannot see, track, contact or rescue anyone.
3. For a no-permission alternative, expand **Scripted browser demo (not AI, no live voice)** and use its text choices. Leave optional speech/microphone controls untouched. This is a separate labelled script, never an automatic fallback when AI fails.
4. **Routes** offers fictional seeded destinations and map comparison. Explicit searches/walking directions use public Photon/FOSSGIS OSRM services; outages show labelled dashed seeded fallback paths. Neither live nor fallback routes guarantee safety.
5. **Circle/Reports** contain fictional local demo community data. Posts/replies remain pending until demo moderator review; approval checks community standards, not factual truth. Demo role switching is not real authentication.
6. Real private **Journey/guardian SOS** needs **two separate signed-in accounts**: traveller and an explicitly opted-in guardian. Choose recipients and review each alert. The guardian inbox must be open; retrieval/read and acknowledgement are distinct. There is no authority dispatch, background/push delivery, automatic WhatsApp or AI escalation. Keep real testing consensual; demo alerts are separate.

## Verification boundaries

Real microphone/audio, audible pickup, conversation quality and live provider latency **have not been tested**. Mocked relay tests and synthetic rollback SQL checks do not prove a working audible call. No real call, account, send or device-permission prompt was used in this audit. No hackathon submission or private submission-hub changes were made.
